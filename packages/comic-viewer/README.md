# 토끼 뷰어 — 두 쪽 보기

버전 `261105000003`. **한 화면에 만화 두 페이지를 가로로 나란히 표시하는 뷰어**입니다. 한 이미지에 두 페이지가 합쳐진 합본은 화면 전체 너비에 표시합니다. Android Firefox와 데스크톱에서 같은 두 쪽 보기를 사용합니다.

## 설치

`npm run build:comic-viewer`로 생성한 `dist/comic-viewer.user.js` 전체로 Tampermonkey의 기존 스크립트를 교체하고 저장한 뒤 웹페이지를 새로고침하세요. 다른 토끼 뷰어가 함께 실행 중이라면 꺼서 중복 실행을 피합니다. 페이지에 **두 쪽 보기** 버튼이 표시됩니다.

## 사용

- **두 쪽 보기**를 누르면 첫 번째와 두 번째 페이지가 함께 표시됩니다. 가로 방향으로 기기를 돌리면 더 크게 읽을 수 있습니다. 세로 화면에서도 두 페이지 배치를 유지합니다.
- 원본 이미지의 **가로 ÷ 세로 비율이 1.2 이상**이면 합본으로 자동 판단해 자르지 않고 화면 전체 너비에 맞춥니다. 합본 직전의 일반 페이지는 혼자 표시하고, 합본 다음부터 다시 두 장씩 묶습니다. 예를 들어 2번 이미지가 합본이면 **1 → 2(합본) → 3–4 → 5–6** 순서입니다. 쪽수는 원본 이미지 번호를 유지합니다.
- 자동 판단이 맞지 않으면 메뉴가 보일 때 **각 이미지 오른쪽 위의 사각형 아이콘**을 누르세요. 해당 이미지를 **단독 보기 / 두 쪽에 묶기**로 전환합니다. 원본 비율과 관계없이 선택이 우선하며, 뷰어를 닫으면 초기화됩니다. 이 아이콘도 하단 메뉴와 함께 숨겨집니다.
- **두 쪽 보기** 버튼이나 `i` 키로 직접 진입하면 주소창을 숨기는 전체화면을 동시에 요청합니다. 요청이 거절되면 뷰어 안의 **전체화면** 버튼으로 다시 시도할 수 있습니다. **전체화면 해제**로 돌아올 수 있고, 뷰어의 **닫기**를 누르면 이 뷰어가 시작한 전체화면도 종료합니다. 브라우저가 요청을 거절하면 이유를 표시합니다. 전체화면 전환에는 사용자 입력이 필요합니다([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)).
- 조작 메뉴는 하단 중앙의 둥근 반투명 패널로 표시됩니다. 화살표 사이에 현재 쪽수를 표시하고, 읽기 방향·첫 장 단독·전체화면·닫기는 아이콘 버튼으로 배치합니다. 아이콘에는 접근성 이름과 도움말을 유지하며, 첫 장 단독 설정은 켜지면 푸른색으로 표시됩니다. 메뉴는 이미지 위에 겹쳐 표시되므로 이미지 높이를 차지하지 않습니다. 메뉴는 3초 후 자동으로 숨겨지며, 이미지 화면을 탭하면 다시 표시하거나 숨길 수 있습니다. 전체화면 진입 시에는 바로 숨깁니다.
- **다음 2쪽 / 이전 2쪽** 버튼 또는 가로 스와이프로 펼침 단위로 넘깁니다. 합본이나 단독 페이지는 한 장씩 넘어갑니다. 마지막 페이지 수가 홀수이면 남은 한 페이지만 표시합니다.
- 페이지 이동 화살표 옆의 **겹화살표**는 **이전화 / 다음화**입니다. 회차 중간이나 마지막 두 쪽에서 바로 이동할 수 있으며, 이동할 회차가 없으면 흐리게 비활성화됩니다. 다음 회차가 준비되면 두 쪽 보기를 자동으로 다시 엽니다. 페이지가 새로 로드되면 전체화면은 **전체화면** 버튼으로 다시 켜야 할 수 있습니다.
- 마지막 펼침에서 다음 방향으로, 첫 펼침에서 이전 방향으로 스와이프하면 페이지를 이동하는 대신 메뉴를 표시합니다. 이미 메뉴가 보이면 그대로 유지합니다.
- 만화는 기본적으로 오른쪽→왼쪽 순서입니다. **읽기: 우→좌** 버튼으로 방향을 바꿀 수 있습니다. 우→좌일 때 오른쪽으로 스와이프하면 다음 두 쪽으로 이동합니다.
- 표지 다음부터 페이지 짝을 맞추려면 **첫 장 단독**을 켜세요. 첫 장은 단독으로, 이후에는 2–3, 4–5쪽으로 표시합니다. 기본값은 1–2, 3–4쪽입니다. 켜기·끄기 선택을 같은 사이트의 브라우저에 저장해 뷰어 재진입, 회차 이동, 새로고침 뒤에도 유지합니다. 브라우저가 저장소를 차단하면 현재 페이지를 열어 둔 동안만 유지됩니다.
- `i`: 열기/닫기, `j`/`k`: 다음/이전 두 쪽, `Esc`: 닫기. 좌우 화살표는 읽기 방향을 따릅니다. `l`/`h`는 다음화/이전화입니다.
- 현재 두 쪽을 읽는 동안 다음 두 쪽을 낮은 우선순위로 미리 불러옵니다. 넘길 때 미리 받은 이미지 객체를 재사용합니다. 이전 두 쪽도 잠시 보관해 되돌아갈 때 활용합니다.
- 이미지가 늦게 도착해도 페이지 번호를 유지합니다. 로드 뒤 합본으로 판명되면 현재 이미지가 포함되도록 묶음을 조정하며, 다음 이동에서 나머지 이미지를 이어 보여줍니다. 실패한 이미지는 해당 칸의 **다시 시도**로 다시 불러옵니다.

## 구현과 검증

간편 세로 뷰어와 자동 전환을 제거했습니다. 외부 React 뷰어와 스크롤 라이브러리 없이 동작하며, 두 쪽 배치는 일반 화면에서도 동작합니다. 직접 진입할 때와 **전체화면** 버튼을 누를 때 네이티브 Fullscreen API를 사용합니다. 다음화 자동 복귀에는 새 사용자 입력이 없으므로 전체화면을 자동 요청하지 않습니다. `<dialog>` 자체는 전체화면 대상으로 허용되지 않아 문서 루트에 요청하고, 열린 뷰어를 그 위에 표시합니다. 일반 이미지에는 화면 너비를 각각 절반씩, 합본·수동 단독 이미지에는 전체 너비를 배정하고 `object-fit: contain`으로 잘리지 않게 맞춥니다. 현재 펼침과 다음 펼침의 이미지를 요청합니다. 이전·현재·다음의 최대 여섯 이미지 객체를 보관하며 범위를 벗어나거나 뷰어를 닫으면 이벤트와 주소 참조를 정리합니다. 진행 중인 네트워크 요청의 실제 취소 여부는 브라우저가 결정합니다.

합본 판별에는 로드된 이미지의 `naturalWidth`와 `naturalHeight`를 사용합니다. 사이트의 원본 이미지가 이미 로드돼 있으면 그 크기를 사용하고, 그 외에는 뷰어 이미지나 미리 불러온 이미지의 로드 완료 시 판별합니다. CSS 표시 크기나 기기 방향은 판별에 사용하지 않습니다. 지연 로딩용 대체 이미지의 크기는 실제 URL과 일치하지 않으면 무시합니다. 비율을 이용한 추정이므로 가로 삽화 등은 수동 전환으로 보정할 수 있습니다.

새 테마의 `theme-viewer-data`와 이미지 슬롯, 기존 `.vw-imgs` 및 `.view-padding` 구조를 읽습니다. SPA 회차 변경 시 이전 이미지가 섞이지 않도록 회차 정보와 기존 이미지 요소를 확인합니다. 이미지 변화는 MutationObserver로 감지합니다.

회차 이동 버튼, 사이트의 이전화·다음화 링크, Navigation API의 이동 시작 이벤트에서 이전 회차 이미지 목록을 고정합니다. 이동 중 이미지 DOM이 URL·메타데이터보다 먼저 갱신돼도 새 이미지가 이전 회차 이미지로 차단되지 않습니다. 이동 시작 신호 없이 임의로 DOM과 URL을 변경하는 경우에는 이미지 소속을 확정할 수 없어 기존의 보수적인 차단 방식을 유지합니다. URL이 없는 원본 슬롯의 로딩 실패·복구 상태도 뷰어에 즉시 반영합니다.

저장소 루트에서 `npm ci` 후 `npm test`로 호환성을 검증합니다. `npm run dev:comic-viewer`로 개발 서버를 실행하고, `npm run build:comic-viewer` 또는 `npm run build:all`로 설치 파일을 생성합니다. 빌드 결과의 실행 검증은 `npm run test:build --workspace=packages/comic-viewer`로 실행합니다. 소스는 `src/main.js`, 메타데이터는 `userscript.json`, 설치 파일은 `dist/comic-viewer.user.js`입니다. 실제 `/manhwa/10454/103310` 페이지에서 수집한 33개 슬롯 구조를 사용해 두 쪽 배치, 페이지 이동, 표지 정렬, 읽기 방향, 터치, 부분 실패, 회차 전환을 검사합니다. jsdom에서는 레이아웃 렌더링과 실제 이미지 다운로드를 검증할 수 없어 CSS 속성과 DOM 상태를 검사합니다. 실제 모바일 Firefox 화면 검증은 아직 하지 못했습니다.

사용자는 `.user.js` 파일 하나만 설치하면 됩니다. npm, Vite, jsdom은 개발·빌드·테스트용입니다.
